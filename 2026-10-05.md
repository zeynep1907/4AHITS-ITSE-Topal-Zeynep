## logische Argumentationskette
 
**Warum AES-256-CBC für das Verschlüsseln der einzelnen Dateien?**
 
+ Es bietet die notwendige hohe Geschwindigkeit, um möglichst viele Dateien zu verschlüsseln, bevor die Ransomware entdeckt wird.
 
**Warum ein eigener Key für jede Datei?**
+ Es verhindert, dass das Opfer durch den Fund oder die Freigabe eines einzigen Schlüssels alle Dateien auf einmal entschlüsseln kann.
 
**Warum wird dieser AES-Key dann RSA-verschlüsselt?**
+ Es sichert den symmetrischen Schlüssel auf dem System. Nur der Angreifer kann es mit seinem privaten RSA-Schlüssel wieder entschlüsseln.
 
**Warum an die Datei angehängt?**
+ Es ermöglicht eine fehlerfreie Zuordnung. Der Entschlüssler findet den passenden Key direkt in der Datei.
 
**Warum wird der victim RSA private key dann AES-verschlüsselt?**
+ Es schützt den lokal generierten privaten Schlüssel des Opfers, damit das Opfer es nicht selbst zur Entschlüsselung auslesen kann.
 
**Warum wird ein globaler RSA-Key verwendet, um aes_victim_key zu verschlüsseln?** 
+ Er fungiert als Master-Key des Angreifers. Stellt sicher, dass die Entschlüsselung ohne die Freigabe des Angreifers mathematisch unmöglich bleibt.

## Übung 1.2 (Ryuk - Red Team)
 
Zuerst wurde der Befehl 

```
┌──(kali㉿kali)-[~]
└─$ nano ryuk_ransom
```

eingegeben und der Nano gestartet.

Anschließend wurde das Bash-Skript eingegeben und gespeichert

```
#!/bin/bash
 
if [ $# -eq 0 ]; then
    echo "Keine Dateien angegeben!"
    exit 1
fi
 
for file in "$@"
do
    if [ -f "$file" ]; then
        echo "Datei gefunden: $file"
        echo "Simulation der Verarbeitung: $file"
    else
        echo "Datei nicht gefunden: $file"
    fi
done

echo ""
echo "================================"
echo "          RANSOM NOTE"
echo "================================"
echo "Dies ist eine Sicherheitssimulation."
echo "Es wurden keine Dateien verschlüsselt."
```

Um das Skript zu testen, wurde 3 Testdatein erstellt.

```
┌──(kali㉿kali)-[~]
└─$ touch test1.txt test2.txt test3.txt
```

Das Skript wurde mit dem befehl gestartet:

```
┌──(kali㉿kali)-[~]
└─$ ./ryuk_ransom test1.txt test2.txt test3.txt
```

Ergebnis:

```
Datei gefunden: test1.txt
Simulation der Verarbeitung: test1.txt
Datei gefunden: test2.txt
Simulation der Verarbeitung: test2.txt
Datei gefunden: test3.txt
Simulation der Verarbeitung: test3.txt

================================
          RANSOM NOTE
================================
Dies ist eine Sicherheitssimulation.
Es wurden keine Dateien verschlüsselt.
```

Alle 3 Datein wurden gefunden und die Ransom Note wird angezeigt.

Als nächstes wurde getestet, was passiert, wenn eine angegebene Datei nicht existiert.

```
┌──(kali㉿kali)-[~]
└─$ ./ryuk_ransom test1.txt hallo.txt          
Datei gefunden: test1.txt
Simulation der Verarbeitung: test1.txt
Datei nicht gefunden: hallo.txt

================================
          RANSOM NOTE
================================
Dies ist eine Sicherheitssimulation.
Es wurden keine Dateien verschlüsselt.
```

+ test1.txt existiert und wurde gefunden
+ hallo.txt existiert nicht und als nicht vorhanden gemeldet.

Danach wurde das Skript ohne Dateinamen gestarteet.

```          
┌──(kali㉿kali)-[~]
└─$ ./ryuk_ransom                    
Keine Dateien angegeben!
```

Als nächstes wird überprüft, ob OpenSSL auf Kali vorhanden ist.

```
┌──(kali㉿kali)-[~]
└─$ openssl version
OpenSSL 3.5.0 8 Apr 2025 (Library: OpenSSL 3.5.0 8 Apr 2025)
```

Es wird eine neue Testdatei erstellt.

```
┌──(kali㉿kali)-[~]
└─$ echo "Testdatei" > test.txt 
```

und der Inhalt wird kontrolliert.

```
┌──(kali㉿kali)-[~]
└─$ cat test.txt        
Testdatei
```

Danach wurde ein SHA-256-Has berechnet.

```
┌──(kali㉿kali)-[~]
└─$ openssl dgst -sha256 test.txt
SHA2-256(test.txt)= c97c2e1584695ad30ef8622fcbda73d886314eee7e856c5c6944831644ddbee3
```

+ openssl startet Kryptographie
+ dgst berechnet digitale Hashwert
+ -sha256 legt SHA-256-Algorithmus fest


Die Datei wurde noch einmal mot `cat`angezeigt und der Hash noch einmal berechnet.

```
┌──(kali㉿kali)-[~]
└─$ cat test.txt
Testdatei
                                                                             
┌──(kali㉿kali)-[~]
└─$ openssl dgst -sha256 test.txt
SHA2-256(test.txt)= c97c2e1584695ad30ef8622fcbda73d886314eee7e856c5c6944831644ddbee3
```

Hashwert ist identisch.

Als weiterer Versuch wurde Base64 verwendet.

```
┌──(kali㉿kali)-[~]
└─$ base64 test.txt > test.txt.b64
```

Ergebnis:

```
┌──(kali㉿kali)-[~]
└─$ cat test.txt.b64
VGVzdGRhdGVpCg==
```

Base64 ist keine Verschlüsselung, deswegen können die Datein ohne Passwort wider zurück gewandelt werden.

Eine weitere Testdatei wurde für die Verschlüsselungsdemonstration erstellt.

```
┌──(kali㉿kali)-[~]
└─$ echo "Meine geheime Testnachricht" > demo.txt
```

Anschließend wurde die Datei mit OpenSSL verschlüsselt.

```
┌──(kali㉿kali)-[~]
└─$ openssl enc -aes-256-cbc -salt -pdkdf2 -in demo.txt -out demo.enc
enc: Multiple cipher or unknown options: -aes-256-cbc and -pdkdf2
enc: Use -help for summary.
```


+ openssl startet OpenSSL
+ enc verwendet die Verschlüsselungsfunktionen
+ -aes-256-cbc verwendet den Verschlüsselungsalgorithmus AES-256-CBC
+ -salt verwendet einen zusätzlichen zufälligen Salt-Wert
+ pbkdf2 verwendet PBKDF2 zur Ableitung eines kryptografischen Schlüssels
+ -in demo.txt gibt die Eingabedatei an
+ -out demo.enc legt die verschlüsselte Ausgabedatei fest

Überprüfung:

```
┌──(kali㉿kali)-[~]
└─$ file demo.enc
demo.enc: openssl enc'd data with salted password
```

Danach wurde die verschlüsselte Datei wieder entschlüsselt.

```
┌──(kali㉿kali)-[~]
└─$ openssl enc -d -aes-256-cbc -pbkdf2 -in demo.enc -out demo_wiederhergestellt.txt
enter AES-256-CBC decryption password:
```

Anschließend wurde die Wiederhergestellte Inhalt angezeigt.

```          
┌──(kali㉿kali)-[~]
└─$ cat demo_wiederhergestellt.txt
Meine geheime Testnachricht
```

Ursprüngliche Datei wurde erfolgreich wiederhergestellt werden
